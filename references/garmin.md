# Garmin MCP Rules

## 定位

Garmin 是持续训练数据的首选来源，但必须通过用户已配置的 MCP 实际调用。仅有 MCP 配置或工具名称，不等于成功读取数据。所有默认操作只读。

## 首次探测

1. 列出当前可用工具，确认活动列表、活动详情、每日统计、睡眠、HRV、训练状态/恢复等只读能力。
2. 用小窗口做只读测试：最近 14 天活动、昨天每日统计、最近 7 天睡眠、最近 21 天 HRV。
3. 核对返回字段、日期格式、时区、分页（`has_more`/`next_page`）和最新数据日期。
4. 把失败、缺失权限、空字段和最新日期写进 `coach/DATA_AUDIT.md`。
5. 只有实际返回成功，才能说“已检查 Garmin”。

建议先生成查询计划：

```bash
python .training_os/bin/training_os.py garmin-plan --today 2026-01-01
```

## 每次增量检查

默认重叠窗口为 3 天，防止补录和修订被漏掉：

```text
start = max(today - initial_days, last_checked_date - 3 days)
end   = today
```

必须核对：

- 最近活动列表，按 `start_date`、`end_date`、分页遍历；
- 新活动 ID 的详情；
- 今天和昨天的每日统计；
- 最近 7 天睡眠摘要；
- 最近 21 天 HRV 趋势；
- 今天训练状态、恢复时间（设备支持时）；
- 与上次水位线相比的新增、修订、删除/缺失。

同一天多个活动可能是真实的两次训练，也可能是一次活动被拆分。证据不足时保留并标记，不能静默合并。

## 去重

优先级：

1. 平台唯一活动 ID；
2. 来源 + 开始时间 + 距离 + 时长；
3. 日期 + 类型 + 距离/时长 + 平均心率；
4. 仍不确定时保留两条，标记“疑似重复”。

不同来源不能因为“看起来一样”直接删除。若旧记录被修订，记录前值、新值、检查时间和依据。

## 写入原始证据

MCP 返回后，用命令保存，不要手工截断关键字段：

```bash
python .training_os/bin/training_os.py garmin-record \
  --input batch.json \
  --tool get_activities_by_date \
  --window 2026-01-01:2026-01-15 \
  --latest-activity-date 2026-01-14 \
  --latest-data-date 2026-01-15 \
  --status success
```

`batch.json` 是工具返回的完整 JSON。命令会写入 `data/garmin/raw/`、更新 `state.json`，并追加审计记录。

## 数据解释

- 设备时间、用户手动计时、正式比赛枪声/净计时是不同口径。
- `null`、0、缺失字段不能自动解释为真实零值。
- 单日 HRV、睡眠分数和训练状态只作趋势参考，不能单独决定训练。
- 设备估算的 VO2max、恢复时间、卡路里不是实验室测量，也不能替代用户选择的测试或训练体系。
- 疼痛、疾病、药物、月经周期、旅行和高原等信息若用户未提供，不得编造。

## 安全

- 胸痛、晕厥、异常呼吸困难：停止运动并建议及时就医。
- 持续或加重疼痛、明显跛行、日常活动受影响：暂停相关高强度训练并建议专业评估。
- 任何上传课表、修改区间、写云端数据的工具，默认禁用；只在用户当次明确授权后执行。

## MCP 配置模板

安装器会在 `.training_os/mcp/` 生成 Codex、Claude Code 和通用 JSON 模板。模板只含占位符，不含 token。

常见本机认证流程（以实际安装包为准）：

```text
garmin-mcp-auth
garmin-mcp
```

认证 token 通常保存在用户主目录的私有目录中，不进入项目。若工具不存在，先让用户安装其选择的 Garmin MCP 实现，不要伪造服务器或抓取网页。
